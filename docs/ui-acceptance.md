# Приёмка интерфейса 0.2 из архива

Основание: cargonomica-utm-qr-ui.zip и согласованный tmp/plans/ui-archive-adaptation.md. Исходный архив сохранён. Копия до изменений — tmp/pre-ui (без секретов/vendor). Новые файлы интерфейса: plugin/cargo-utm/views/workspace.php, assets/ui/app.css, assets/ui/app.js, src/Workspace.php, src/Tracking.php.

## Фактически проверено агентом

- PHP-синтаксис изменённых исходников и тестов, sh -n скриптов.
- Node syntax для нового app.js и прежнего admin.js.
- 98 доменных утверждений, включая прежнюю URL-фикстуру и новые print_media/source/Roistat/rs/macros/encoding/лимиты.
- 13 проверок реального диспетчера Workspace::api в изолированном процессе со стабами WordPress: anonymous/viewer/editor, nonce, POST, неизвестная операция, чтение реестра, некорректный JSON/скаляр. Это не проверка живой HTTP/WP-авторизации.
- Статический HTML/JS-контракт: 90 статических ID, шесть офлайн-кнопок, наличие целевых элементов JS, активы/шрифты, отсутствие localStorage/innerHTML/JS QR, область CSS. Не заменяет браузерный рендеринг.
- Генерация SVG новым фирменным профилем через установленную библиотеку chillerlan на локальном CLI. PNG и независимое декодирование нового профиля должны пройти на контейнерном стенде.
- Composer JSON, YAML и docker compose config --quiet.

Не выполнены агентом: миграция живой БД, применение релиза, новые интеграционные/HTTP тесты и визуальная проверка. Причина: Docker socket и сетевые сокеты недоступны в сессии; браузерного инструмента/установленного браузера нет. Старый релиз прошёл тесты по предыдущему выводу пользователя, что не доказывает готовность нового.

## Последовательность на стенде

1. `./scripts/upgrade-ui.sh` — резервная копия, снимок выпущенных записей, пересборка/миграция и сравнение снимков. Требуются успешный PASS сохранности записей, Cargo setup completed и nginx -t.
2. `./scripts/integration.sh` — новые семь типов, идемпотентность, Roistat, перенос назначения, карточка/реестр, повторная миграция; SVG/PNG всех действующих профилей. Требуется финальный PASS QR-декодера.
3. `python3 tests/http.py` — прежние 401/404/302/410/405 и GET/HEAD/повторный GET.
4. Подключить браузер через PuTTY на Windows: туннель local 443 -> server 127.0.0.1:18443 и hosts utm.cargo.test/go.cargo.test -> 127.0.0.1. Не публиковать origin ради теста.

## Ручные сценарии браузера

- Вход Basic Auth и WordPress, меню UTM и QR. Внешний вид совпадает с архивом: монохромная боковая панель, локальная типографика, вкладки онлайн/офлайн, карточка формы и предпросмотра, реестр и диалог. На узкой ширине элементы доступны и не перекрываются. Служебная WP-навигация сохранена.
- До сохранения нет рабочей короткой ссылки/скачивания QR. Метки появляются после серверного предпросмотра. Ошибки URL/обязательных полей/slug видны без потери ввода. Если имя слишком длинное, оно не обрезается молча.
- Выбрать юнит: доступны только его кампании и общий/собственный профиль. Создать кампанию: год и редактируемый серверный slug, конфликт имени кода, возврат к форме с выбранной кампанией.
- Каждый из шести офлайн-носителей, включая печатное издание/выпуск/полосу. Выставка/конференция требуют дату/город/место. Для транспорта проверить checkbox. При переключении носителей введённые поля сохраняются в текущей странице.
- Онлайн: выбрать все пресеты, при необходимости изменить source/medium. Roistat: числовой ID для yandex/vk/avito, строка для tg/ручного. Проверить макросы в полной ссылке и различие rs/roistat. Отключение дополнительных меток не удаляет неуправляемые параметры исходного URL.
- Сохранить, повторить нажатие без изменения: одна запись/один QR. При сетевом обрыве повтор возвращает прежнюю запись. После изменения поля требуется новый выпуск. Предпросмотр с устаревшим ответом не перетирает результат сохранения.
- Скачать SVG и PNG всех трёх размеров, скопировать ссылки, открыть карточку из реестра и расшифровки. Данные из БД, GET реальные, даты UTC. Проверить диалог, Escape, фокус, клавиатурную навигацию и clipboard fallback.
- Поиск/фильтры/пагинация: юнит/кампания/носитель/статус/город/канал/период. CSV учитывает фильтры; отдельная выгрузка суточных GET. Поля roistat/rs и версия пресета в CSV.
- Дублирование старой записи создаёт новый код с действующим профилем. Старые QR/ссылки/версии после миграции совпадают со снимком.
- Администратор меняет статус и адрес с причиной, tracking/UTM/QR сохраняются, аудит виден. Просмотрщик читает/выгружает, но сервер отклоняет все попытки создания и изменения. Сотрудник создаёт, но не меняет статусы/адреса/справочники. Истёкший/неверный nonce отклоняется.
- Аналитика и справочники открываются из бокового меню; существующие функции этих служебных экранов работают.

## Уточнение проверки QR: строго центральный логотип

После дополнительного запроса пользователя реализован выбор версии QR с безопасным строго центральным окном. Для тестового адреса используется версия 14 / матрица 73 / окно 9 вместо смещения в матрице версии 7. Защитные поля и служебные элементы сохраняются. PNG дополняется симметрично при чётном целочисленном масштабе. Четыре локальных SVG-проверки геометрии/функциональных модулей прошли. Независимые PNG/Inkscape-тесты дополнены проверкой центрирования, но после этой правки ещё не запускались на контейнерном стенде. Ранее выданные SVG остаются прежними; проверять новое положение на новом выпуске/дубликате. Визуальное центрирование определяется заданным viewBox профиля; контуры профиля должны быть правильно подготовлены.

## Размер знака и белое окружение

По запросу пользователя логотип увеличен на 25% по линейным размерам относительно предыдущего центрального варианта. Белая подложка даёт отступ 10% ширины логотипа на каждой стороне. SVG и PNG используют один сохранённый вектор. Для тестового адреса это logo10/подложка12 модулей, по центру QR версии14; все затрагиваемые модули проверены как data. 4 локальных SVG-теста и check.sh прошли, проверка размеров подложки добавлена в независимый QR-декодер. Контейнерный decode после этой правки и визуальный результат ещё не подтверждены; старые SVG остаются прежними.

## Главная и индексация

По запросу пользователя корень сайта ведёт в UTM/QR: гость получает200 с отдельным генератором, авторизованный пользователь с cargo_view —200 с приложением, пользователь без прав —403. После обычного входа пользователь сервиса попадает в приложение; глубокие ссылки карточек сохраняются.

Для страниц и файлов задан X-Robots-Tag noindex/nofollow/noarchive, WordPress meta robots и запрет публичной индексации в option_blog_public. robots.txt разрешает чтение запрета: согласно [документации Google](https://developers.google.com/search/docs/crawling-indexing/block-indexing), блокировка обхода Disallow:/ мешает роботу увидеть noindex на уже известных URL. Это не обещает мгновенного удаления ранее попавших в поисковую выдачу страниц. Авторизацию продолжает обеспечивать WordPress.

Локально пройдены новые проверки SitePolicy (headers/meta/robots и10 сценариев), синтаксис и общийcheck.sh. После пересборкиwordpress/recreateoriginNginx проверить публичные /, /wp-login.php, /robots.txt и файлSVG: правильные redirect/noindex, отсутствиеBasicAuth и сохранность закрытых обработчиков. Существующие записиблога иданные не удалялись.


## Открытый генератор: проверка после обновления

Локальные проверки 16 ноября: scripts/check.sh PASS (IDN-пример пропущен из-за отсутствия intl). Включены 28 проверок публичного API с запретом любых записей и чтения внутренних таблиц, 10 проверок оболочки/входа/прав, восстановление онлайн/офлайн-черновика и 9 тестов установщика HTTPS. После пересборки wordpress и пересоздания nginx:

4. Очистить форму: черновик и гостевое название/код сброшены. Устаревший черновик старше суток не восстанавливается.
5. python3 tests/http.py проверяет открытую оболочку, публичный nonce и запрет гостевых операций, затем прежние редиректы и счётчики по существующим integration fixtures. Полный integration.sh создаёт тестовые данные; не запускать его на реальных данных без согласованного тестового контура.

Старые short_code, UTM, QR и записи не мигрируются этой правкой. Визуальная и контейнерная приёмка этого обновления ещё не выполнена.
